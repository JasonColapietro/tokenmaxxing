Token Costs, Real Value: How Suede AI Prices Agent Work for Clients

Jason Colapietro on keeping agent engagements on the right side of the tokenmaxxing line: price the finished task, cap the meter, report the line from cost to value.

By Jason Colapietro, Founder and CEO, Suede AI · West Palm Beach, FL · November 14, 2026

A token costs a fraction of a cent. An agent that runs for an afternoon can burn millions of them. That gap is why “what will this cost?” is the hardest question a client asks Suede AI, and why we never answer it with a per-token rate card.

This note explains how Suede prices agent work, using the same lens Jason Colapietro applies to the AI economy in the Tokenmaxxing essay. The essay asks whether anyone can draw a line from AI spend to delivered value. Our pricing model exists to draw that line for every client.

Why we do not resell tokens

The essay describes what happens when consumption becomes the goal. Uber built a leaderboard that ranked teams by tokens burned, per-engineer costs reportedly ran $500 to $2,000 a month, and a full year’s AI coding budget was gone in four months. Its COO then said the link between that spend and anything riders would notice “is not there yet.”

An agency that marks up tokens has the same broken incentive in miniature: it earns more when its agents work less efficiently. Suede AI prices the deliverable and treats model usage as a cost we manage on the client’s behalf and report in the open. The meter is an input we work to shrink, not a product we sell.

The three parts of every agent engagement

Every agent project Suede scopes breaks into three parts, and each is priced on its own terms.

Build. Designing the workflow, writing the tools, wiring the integrations and testing the failure cases. This is fixed-scope engineering against a written spec, the discipline Jason Colapietro documents in The Claude Code Bible and Codex in Production.

Run. Model calls, hosting and monitoring once the agent is live. This is the metered part, and it is where the caps live.

Improve. A scheduled review against the outcome metric. Is the agent still doing the job, and is it doing it for less this month than last month?

Splitting the three keeps a client from paying engineering rates for compute, or paying compute prices for engineering that never got done.

Caps first, estimates second

Before an agent touches client data, Suede AI sets a hard spending ceiling on every key it uses, with alerts well below the ceiling. The reported $500 million accident in the essay came from one missing setting. We treat that setting as part of the build, not an afterthought.

Estimates come from a pilot rather than a guess. We run the agent on a real sample of the client’s work, measure tokens per completed task, multiply by expected volume and add headroom. The client sees the cost per finished task, which is a number a business owner in West Palm Beach or Jupiter can compare directly to the cost of doing the same task by hand. If the agent is not cheaper or better per task, the honest answer is not to build it, and we say so.

Routing each step to the cheapest model that passes

Not every step needs a frontier model. Classification, extraction and formatting often run well on smaller models, while planning and reasoning steps get the larger ones. Suede keeps evaluation cases for each step, so switching a step to a cheaper model is a tested change instead of a hope.

That habit comes from contributing to other people’s code. Jason Colapietro has 54 pull requests merged across 46 open-source repositories he does not maintain, including Jest, Adobe React Spectrum, Backstage and the Polkadot SDK. Each of those passed a maintainer’s test suite before it landed. Agent steps get the same treatment: no test, no swap. If you want an outside score for an agent you already run, Agentix grading notes walk through how we evaluate agent behavior.

What a client receives every month

  • Tasks completed and cost per task, compared with the prior month.
  • Cap headroom on every key, with any alert that fired.
  • Changes made: model swaps, prompt revisions and new evaluation cases.
  • Failures flagged for human review, with what we changed in response.

That report is the line Uber’s COO said he could not yet draw. Drawing it is the job.
